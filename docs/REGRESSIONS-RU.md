# Ошибки, которые должны оставаться в бенчмарке

Корпус `catalogue-regressions-v1` сохраняет8 важных случаев с3 страниц:
назначение демонстрационной страницы, ошибочное сопоставление таблиц по
номеру, спорный символ З/Э, приоритет логотипов, реальную ошибку слова,
повторные увеличения и неверный формат первого review. Чертежи ОПН27/39
также остаются в прежнем наборе v2, ссылки на них есть в реестре.

Для каждого случая записаны source SHA, физическая страница, точные JSON
и их контрольные суммы, фактические версии программы и модели. Исходные
PDF и сырые транскрипты не публикуются. Регистрация не вызывает модели.

```bash
catalog-bench regressions
catalog-bench regressions --case small4-software-example --candidate page4.json
catalog-bench regressions --case innov181-engineering-identities --candidate page181.json
catalog-bench regressions --register new-case.json --registry regressions
catalog-bench regressions --registry regressions
```

Новые примеры сразу попадают в `inbox` со статусом `pending_adjudication`.
Это сохраняет ошибку и её свидетельства, но не превращает догадку в эталон.
Подтверждённый случай включается в следующую версию корпуса после проверки
оригинала. Повторная регистрация того же свидетельства идемпотентна;
изменённый случай требует нового ID, прежний не перезаписывается.

На странице4 Малого каталога описана программа и показан пример проектной
спецификации. Ожидается контекст `software_demonstration`, исходное
свидетельство такого назначения и отсутствие таблиц, продвигаемых как
каталожные позиции. Это три автоматические проверки назначения/области,
а не полная оценка качества смыслового описания. Старый JSON без этого
контекста считается неклассифицированным по новому контракту; это само
по себе не доказывает, что старая программа выдумала товары.

Случай Инновации181 проверяет сохранение действительно напечатанных
необычных марок АС70/72 и АС95/141. До и после грамматической правки
сохранённые файлы проходят2/2 инженерные проверки. Правка
«шлейфовые» → «шлейфовых» отдельно сохранена как буквальный диагностический
случай: она не приносит дополнительных баллов смысловой точности.
Для спорного З/Э фиксированное правильное значение не назначено.
Скорость, лишние вызовы и косметические придирки учитываются отдельно.

Прежние наборы15страниц/500фактов и17страниц/520фактов+21drawing check
не менялись. Новые проверки не смешиваются с их историческими процентами.

Следующие два случая сохранены отдельно в [очереди разбора](../examples/catalogue-regressions-inbox): ложное расхождение из-за разного разбиения областей и неверное название программы при верной классификации назначения. Их точные JSON из неуспешной пробы1.5.0 сохранены; они pending и не добавляют баллов. Проверка: `catalog-bench regressions --registry examples/catalogue-regressions-inbox`.
