# Как выбирать инструменты для оцифровки каталогов

Цель — меньше ошибок в итоговом JSON агента. Высокая оценка отдельного парсера ещё не доказывает, что подключение этого парсера улучшает работу агента.

## Когда и как применять

| Признак исходной страницы | Инструмент и действие | Что проверить по оригиналу |
|---|---|---|
| Читаемый текстовый слой и обычный текст | AnyDoc / native PDF extraction; сохранить текст и координаты | Полноту текста, буквальные обозначения и переносы |
| Сложная таблица, вложенная шапка, объединения | Docling для первого структурного представления; после inspect прочитать canonical rows и raw spans | Число таблиц и физических колонок, владельца объединённой ячейки, единицы и условия |
| Видимая сетка и спорные границы ячеек | img2table как независимая геометрия; прочитать boxes/spans | Что пусто в источнике, что пропущено парсером, какие значения относятся к нескольким строкам |
| Пропущенная область таблицы или сомнительная иерархия шапки | gmft как второе представление структуры; сопоставить области и дочерние/родительские заголовки | Полный путь параметр → условие → единица → значение; не потерять «не менее» |
| Скан, слабый текстовый слой, сложный OCR/layout | Доступный MinerU / Marker / Paddle в явно указанном режиме и на явно указанном устройстве | Перепутанные буквы/цифры, порядок колонок, потерянные заголовки; GPU сам по себе не означает большую точность |
| Поворот текста, чертёж, допуск, спорная единица/условие | Vision: отдельные области и ориентации, затем сверка со всей страницей | Каждый вид/исполнение; принадлежность размера, число отверстий и допуск |

`inspect_pdf_page` в catalog-to-json 1.4.1 возвращает инвентарь таблиц и headers, но не body cells. Поэтому успешный вызов ещё не означает, что агент получил значения строк. После него нужен `read_parser_artifact(artifact_id, kind="canonical")`, продолжая по next_offset до нужных rows. Для объединений нужен raw geometry/spans. Если возвращён только список headers, нельзя утверждать, что body evidence уже проверено.

Пустое значение, unknown и объединённая ячейка — разные состояния. Перед созданием blank проверить исходную область и владельца объединения. Родительский и дочерний заголовки могут вместе задавать «не менее»; отдельные слова «не» и «менее» нельзя интерпретировать независимо. Единица должна принадлежать своему параметру, а не соседнему испытательному току/напряжению. Буквальное наличие правильной цифры недостаточно.

Если парсеры расходятся, большинство не становится эталоном. Агент проверяет спорную область оригинала. Подтверждённую нечитаемость самого источника записывает как source_notes; нерешённую техническую неоднозначность — как uncertainties для проверяющего. Проверяющий читает оригинал самостоятельно и возвращает конкретные проблемы извлекающему агенту.

## Что измерено и что ещё проверяется

[21 конфигурация отдельных парсеров](READY-SOLUTIONS.md) испытана на одинаковых 15 физических страницах и 500 выбранных инженерных фактах. [297 исходных выходных JSON](../examples/parser-outputs/2026-10-12/README.md) опубликованы вместе с версиями, временем и проверяемыми хешами. Это несколько режимов некоторых инструментов, а не 21 независимый продукт. Облачные решения без доступной авторизации не объявляются протестированными.

Исторический A/B фиксировал catalog-to-json 1.4.1, MiniMax M3.1 Flash Preview, 15 страниц и настройки. Первая конфигурация даёт Docling/PyMuPDF4LLM, вторая добавляет img2table/gmft. Сначала измеряется first pass; независимый GLM-проход относится к отдельной стадии. На первых четырёх парах того прогона новые backend не были вызваны, а canonical body после inspect не прочитано. Это промежуточное наблюдение; завершённые результаты1.4.1 и свежего1.4.2 приведены ниже.

В оценщике найдены и исправлены false negatives от склеивания токенов/обычных запятых и false positives от подмены видов чертежа. Grader v0.2.1 сохраняет исходные аннотации и переоценивает прежние JSON отдельной серией; исторические v0.2.0 результаты остаются неизменными.

При проверке описаний учитываем цепочку: инструмент доступен → вызван → вернул результат → строки/геометрия прочитаны → итоговое значение правильно связано с параметром, единицей, условием и изделием. Число вызовов и скорость — вспомогательные показатели. Победителя определяет точность итогового JSON на одинаковых страницах; правила выбора опираются на видимые свойства страницы, без case ID и ответов эталона.

Эти правила вошли в инструкцию1.4.2. Результаты реального прогона приведены ниже; они не подтверждают универсальный выигрыш для всех страниц.

## Проверка инструкции1.4.2

Полный свежий прогон15 страниц:483/500 (96,6%) против479/500 baseline и467/500 extended версии1.4.1. По среднему пяти каталогов новая инструкция92,44%, старый extended92,97%; универсального победителя нет. Все варианты — один последовательный первый проход MiniMaxmedium, без проверяющего/goldfeedback; причинный устойчивый выигрыш не установлен.

Наблюдалось: img2table+canonical на17 —15/15; Docling+canonical на185 —15/15; gmft+полный canonical на38 —72/72; прямые PDF-таблицы/изображения на78 —140/140. Получены12 успешных чтений canonical, raw не читался. Диапазоны API покрыли2 файла до конца; SDK сократил9 ответов, поэтому целиком без сокращения модели предъявлен только gmft38. Полное покрытие API не равно полному предъявлению модели. Один Docling вызов не импортировал shared object в ограничении виртуальной памяти, но агент закончил страницу111 со15/15. END_TURN безфайла на26 считается неудачей общего прогона; отдельный canary1.4.3 не заменяет его. [Точные файлы и протокол](../examples/agent-routing/2026-10-12-body-routing-v1.4.2/README.md).

В parser-plugin0.2.2 (catalog-to-json1.4.4) размер сериализованного ответа ограничен12000байтами при лимите SDK16000. Реальный native MCP/SDK восстановил retained Docling30 точно в4 порциях, max11739байт, без сокращений. Это проверка передачи, не новый замер точности1.4.4; прежний483/500 остаётся результатом1.4.2.
