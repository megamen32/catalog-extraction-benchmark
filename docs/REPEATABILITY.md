# Повторяемость результатов

Сравнивайте минимум три полных раунда одной замороженной программы/модели на одинаковом наборе исходников и независимых фактов. Не заменяйте неудачную страницу удачным повтором. Среднее, минимум, максимум, диапазон и выборочное стандартное отклонение приводятся по полным раундам и каждой странице. Выбранные факты не означают точность всей страницы.

`python -m catalog_bench.repeatability PLAN.json --output results/repeated` сохраняет проверенный первый раунд и запускает два новых. Первый исторический раунд явно отмечен: это не три новых вызова и не рандомизированный эксперимент. Между раундами программа, модель, исходники, AgentPlugin и параметры не меняются. Следующий раунд начинается после окончания всех попыток предыдущего.

План задаёт `rounds` (минимум 3), `initial_concurrency`, `max_concurrency` (максимум 4), `successes_before_increase`, `rate_limit_cooldown_seconds`, `attempt_maximum_seconds`, `deadline_seconds`, `random_seed`, фиксированные `expected_by_case`, независимые `expected_bindings` и `variants`. Вариант содержит `id`, `suite`, `suite_sha256`, `initial_results`, `initial_sha256`, `declared_version`, `model`, `package_version`, `git_revision`, `contract_sha256`, `file_sha256` для исполняемых файлов/конфигурации. Набор случаев, модель, источник, страница и реально исполненная версия сверяются с исходным раундом. Эталоны доступны только оценщику родителя.

Параллелизм растёт после успешных попыток в пределах измеренного конечного бюджета. Обнаруженный 429 уменьшает его и включает паузу перед следующими задачами; сама попытка остаётся в отчёте и не проигрывается заново. Внутренние попытки SDK могут скрыть ограничение провайдера; отсутствие 429 в журнале не доказывает его отсутствия. В отчёте сохраняется история изменения параллелизма. Из-за адаптивной нагрузки сравнение времени ограничено; сумма длительностей задач не является временем всего параллельного раунда.

Результаты каждого вызова сохраняются отдельно. Неизвестное прерывание требует сверки existing native receipts; автоматического повторения неизвестной внешней работы нет. Финальный отчёт возникает только после сохранения всех обязательных попыток. Частичный прогресс не считается полным раундом.

Для трёх новых раундов исходный runner поддерживает `initial_mode: "fresh"`: у вариантов отсутствуют `initial_results` и `initial_sha256`, первый вызов начинается с раунда 1, знаменатель сверяется с независимыми замороженными аннотациями. Историческую когорту в таком режиме подставить нельзя. Режим сохранённого первого раунда остаётся значением по умолчанию.

Fresh-mode добавлен в исходный runner после опубликованного grader 0.2.4; он не входит в неизменённый wheel/tag 0.2.4. При таком составном запуске сохраняйте отдельные Git revision и хеш frozen runner, а также реальную версию и хеш установленного публичного оценщика. Это позволяет расширять запуск без подмены версии алгоритма оценки.

500 фактов распределены неравномерно по каталогам. Наряду с общей долей правильных фактов приводите среднее по каталогам и распределения по страницам. Связи размеров с элементами чертежа, весь свободный текст и все выдуманные подписи не покрыты текущим эталоном. Новые найденные дефекты оформляйте отдельно; не меняйте замороженный набор посреди серии.

[Завершённая серия 1.4.2 и 1.4.4](../examples/agent-routing/2026-10-12-repeated-runs/README.md) сохраняет три полных раунда каждой версии, 84 конечных JSON из 90 попыток, исторические оценки и отдельную полную переоценку опубликованным grader 0.2.4. Скрипт рядом скачивает публичные файлы, проверяет их контрольные суммы и заново считает весь результат без обращения к модели.
